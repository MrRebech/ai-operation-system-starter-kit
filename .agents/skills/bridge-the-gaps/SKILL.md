---
name: bridge-the-gaps
description: Run a user-requested post-onboarding interview to clarify missing or ambiguous business context, saving answers and confirmed updates. Use when the user asks to bridge gaps or deepen understanding of a topic.
---

Run only when the user requests this interview. Read AGENTS.md and context/index.md, then the relevant canonical context and source index. If initial onboarding is unfinished, offer to resume it rather than treating missing answers as a second interview.

Choose five to ten useful questions based on actual gaps, conflicts, or the requested topic. Ask one at a time, adapt to answers, and avoid asking what reliable sources already establish. Explain briefly what the interview will clarify. If fewer genuine gaps remain, finish early rather than padding.

Save each answer immediately to a dated file in `interviews/` with topic, progress, source links, and a resume point. The user may stop at any time. Use a unique filename so earlier interviews remain intact.

Update the canonical context automatically for supported routine details and corrections. Keep tentative ideas labeled separately. Before changing strategy, customer avatar, core products, or resolving a consequential conflict, present the proposed change and obtain confirmation unless the user already explicitly directed that exact update. Keep the pending proposal in the interview until confirmed. Record meaningful confirmed changes in decisions/log.md.

Finish with a short summary of what became clearer, which files changed, and any unresolved issues. No automatic new interview, schedule, or external action.
